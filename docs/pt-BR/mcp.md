# Agentes e MCP

Como um agente de IA conversa com o Paprika: como conectar, as ferramentas que ele recebe e o formato do arquivo por trás de um design. Voltar ao [README](../../README.pt-BR.md).

English: [../mcp.md](../mcp.md).

## Conectar um agente

**HTTP (recomendado, com o canvas aberto):** suba o Paprika (`docker compose up -d --build`, ou `paprika serve` a partir do código) e aponte o agente para `http://127.0.0.1:4777/mcp`. Com Docker, stdio também funciona: veja [docker.md](docker.md).

Claude Code:

```bash
claude mcp add --transport http paprika http://127.0.0.1:4777/mcp
```

**stdio** (agentes que só falam stdio). O processo também sobe o canvas na porta 4777, se estiver livre:

```json
{
  "mcpServers": {
    "paprika": {
      "command": "<CAMINHO>/paprika/server-go/bin/paprika",
      "args": ["mcp", "--db", "<CAMINHO>/design.db"]
    }
  }
}
```

## Ferramentas MCP

| Ferramenta | O que faz |
|---|---|
| `get_design_guide` | Modelo de nós, campos e fluxo recomendado; em inglês, ou em português com `language: "pt-BR"` |
| `get_document_outline` | Árvore compacta + tokens + versão. A primeira linha é `workspace <id> "<nome>"` mais a versão e a contagem de nós. Uma linha `renderer:` lista `wasm` ou `dom` para cada aba conectada, na ordem da conexão, ou `none` quando não há aba. As últimas linhas são a caixa do conteúdo da página (a união dos filhos da página, em qualquer página) e o próximo lugar livre |
| `get_nodes` / `find_nodes` | JSON completo de nós / busca por tipo, nome, texto. `get_nodes` devolve os nós que existem mais `missing: [ids]` (em `structuredContent` e no texto) quando alguns ids sumiram, p. ex. após um undo; só falha se nenhum existir |
| `create_nodes` | Cria árvores aninhadas numa chamada. Devolve `{ids, roots, created, version}`: `ids` é cada id novo (a lista antiga); `roots` é cada nó novo cujo pai não foi criado nessa chamada (`id`, `name`, `type`, `x`, `y`, `width`, `height`); `created` é cada nó novo (`id`, `name`, `type`, `parentId`). O texto é esse JSON mais uma linha por raiz. Num conector `x`/`y`/`width`/`height`/`d` seguem `from`/`to`, então um nó copiado que os traz recebe um aviso, não uma recusa; num path, `normalize: true` leva o desenho para (0,0) e desloca `x`/`y`. `place`: `"free"` (padrão de um nó de topo sem x/y: à direita do conteúdo, mesmo topo, respiro 80, quebra depois de 2400), `"below"`, `"right"`, `{near, side}` ou `"none"` (x/y exatos; dentro de um frame row/column cada raiz também recebe `layoutPositioning: "absolute"` e um aviso diz isso, a menos que você mesmo passe `layoutPositioning`). Um nó novo de topo que sobrepõe outro volta em `warnings` com o lugar livre mais próximo |
| `draw_diagram` | Desenha um diagrama (fluxograma, arquitetura, mapa mental) a partir de formas e ligações: distribui as formas em camadas (`direction`: para baixo ou para a direita, à direita do conteúdo existente) e liga com setas que seguem as formas. Rotas em cotovelo e arredondadas desviam de outras formas no mesmo pai; reta e curva não. Uma ligação pode ter `label` e `route` (`straight`, `elbow`, `rounded`, `curve`) com `radius` / `control` opcionais. `relayout: true` aceita ids de formas que já existem, atualiza `x`/`y` quando vierem e recalcula esses conectores num passo de desfazer |
| `update_nodes` / `move_nodes` / `delete_nodes` | Edição em lote, atômica. `index` nos props do `update` ou no `move` define a ordem Z no pai do nó: número a partir de 0 (o fundo) ou `front` / `back` / `forward` / `backward`, no mesmo passo de desfazer dos outros campos |
| `group_nodes` / `ungroup_nodes` | Põe nós irmãos num `group` (o desenho não se move) / devolve ao pai |
| `align_nodes` / `distribute_nodes` | Alinha 2+ irmãos à caixa da seleção (`edge`: `left` `center` `right` `top` `middle` `bottom`) / distribui 3+ irmãos com o mesmo vão (`axis`: `horizontal` `vertical`). Um desfazer cada. Nó rotacionado usa a caixa alinhada aos eixos. Recusa pai em row/column, conectores e cópias dentro de instância |
| `wrap_nodes` | Põe irmãos num frame novo (transparente, `clip: false`). O desenho não se move. Um desfazer. Devolve `frame` |
| `show_all` / `unlock_all` | Põe `visible: true` em todo nó oculto / limpa `locked`. `pageId` limita à página; omitir cobre o documento. Devolve os ids que mudaram. Sem histórico quando nada muda |
| `combine_paths` | Combina 2+ nós irmãos `path` / `rect` / `ellipse` / `shape` num único `path` (`operation`: `union`, `subtract`, `intersect`, `exclude`). `operations` roda uma sequência numa chamada só (`[{op, ids, as?}, ...]`): o `as` de um passo pode ser usado nos `ids` dos passos seguintes, o último passo é o resultado, e o erro nomeia o passo que falhou (`operations[1] (subtract): ...`); use `ids` + `operation` ou `operations`, não os dois. `style` escolhe o estilo que o resultado mantém: `bottom` (padrão, o mais fundo no z-order), `top`, `first` ou `last` (na ordem em que aparecem), ou `{from: id, fill?, gradient?, stroke?, opacity?, shadow?, outline?, filter?, backdropFilter?}` para copiar o estilo de um nó e sobrescrever campos (`fill` sem `gradient` descarta o gradiente copiado). Apaga as fontes, um passo de desfazer. Retorna `path` (o id novo). Sem menu no canvas nesta ferramenta — agentes usam MCP / `apply_ops` |
| `convert_to_path` | Transforma nós `rect` ou `ellipse` em `path` com o mesmo id. O raio dos cantos entra no `d`. Um desfazer restaura os originais. O menu de contexto do canvas faz o mesmo com o rect ou ellipse do topo sob o ponteiro |
| `duplicate_nodes` | Copia nós com a subárvore inteira num passo só de desfazer. Sem `offset`, `place` cai à direita da origem (respiro 80) para a cópia não pousar em cima; passe `offset` para deslocar x e y, ou `place` `"free"` (depois do conteúdo da página) / `"below"` / `"right"` (ao lado da origem, respiro 80, como `{near: origem, side}`) / `{near, side}` / `"none"`. Também `parentId`, `scale` (tamanhos, texto, traços, espaçamentos e o `scale` das instâncias) e `props` escritos em cada cópia (`{ "mode": "dark" }` faz o par claro/escuro). Instâncias continuam instâncias do mesmo componente; conectores entre nós duplicados passam a ligar as cópias. Retorna `copies` (um id por origem), `map` (cada nó de origem para a sua cópia) e `ids` / `roots` / `created` no mesmo formato do `create_nodes`, mais uma linha de texto por raiz |
| `create_page` | Cria uma página; a primeira leva o canvas atual para "Page 1" quando o documento tem conteúdo (inglês; a UI usa o nome localizado; em documento vazio só a página nova é criada). `ensure: true` com um nome devolve a página que já tem esse nome, em vez de criar uma segunda |
| `round_path_corners` | Arredonda os cantos de um caminho poligonal (`M L H V Z`; curvas são recusadas) com arcos circulares, sem calcular filetes à mão. `d` é um auxiliar puro (devolve o novo `d`, não escreve); `id` atualiza esse nó `path` no lugar (um desfazer, a caixa e x/y ficam). `radius` arredonda todos os vértices; `radii` é um raio por vértice, na ordem escrita (null ou ausente = `radius`, 0 = reto). Cada raio é limitado à metade da aresta adjacente mais curta; pontas abertas ficam retas. Devolve `{d, bounds}` |
| `create_shape_path` | Um nó `path` a partir de uma forma paramétrica: `kind` `star` (`points`, `radius`, `innerRadius`, `angle`, `cornerRadius`), `polygon` (`sides`, `radius`, `angle`, `cornerRadius`), `ring` (`radius`, `thickness` ou `innerRadius`; um caminho com furo, `fillRule` evenodd), `arc` (faixa: `radius`, `thickness` ou `innerRadius`, `startAngle`, `endAngle`, `roundCaps`) e `sector` (fatia: `radius`, `startAngle`, `endAngle`). Ângulos em graus, no sentido horário a partir das 12h. `x`/`y` são o **centro** da forma; `props` leva fill, gradient, stroke etc. (sem fill/gradient/stroke = preenchido com `#000000`). O resultado é um `path` comum (d, width e height são calculados): canvas, screenshot, exportação e o renderizador WASM pintam como qualquer path. Mesmo resultado e `place`/`parentId`/`index` do `create_nodes` |
| `create_component` / `create_instance` / `detach_instance` | Marca um frame como componente (`props` opcionais: text, boolean, variant) / põe uma cópia (`scale`, `overrides`, `propValues`, `slots`; retorna o id de cada cópia, inclusive `slot/id` e caminhos aninhados) / transforma uma instância em nós comuns (o `bind` das cópias é descartado: os valores resolvidos já estão lá). O `bind` é checado no fim da transação, então um só `create_nodes` pode levar os filhos com `bind` e `component: true` no frame deles |
| `detach_tokens` | Troca `$nome` nos nós pelos literais resolvidos no modo de cada nó. `fields` limita os campos; sem ele, desvincula todo token do nó. Numa instância ou numa cópia dela só os overrides que ela possui são desvinculados (`fill` da raiz, `fill`/`color` de uma cópia); os campos que vêm do componente são pulados e listados em `skipped`, sem falhar |
| `apply_ops` | Transação mista (create, update, delete, move, set_tokens, set_assets, rename_document, group, ungroup, add_page, detach, detach_tokens, combine_paths, align, distribute, wrap, reveal, convert_to_path) |
| `propose_tokens` | Lê variáveis CSS, um tema Tailwind (`theme` em JS ou `@theme` do v4) ou tokens JSON (plano ou DTCG `$value` / `value`) em `content` e devolve operações `set_tokens` para o agente aplicar. A origem é o texto do arquivo; um caminho no disco é recusado. Os nomes CSS perdem o `--` inicial (`--color-bg` → `color-bg`; `var(--color-bg)` → `$color-bg`). Os grupos do Tailwind viram nomes com ponto (`colors.brand` → `color.brand`, `borderRadius.md` → `radius.md`). Comprimentos em px viram números. Um seletor ou `prefers-color-scheme` que nomeia um modo vira `mode` nessa proposta |
| `set_tokens` | Design tokens (`$nome`). `type` opcional (`color`, `length`, `fontFamily`, `fontWeight`, `fontSize`, `lineHeight`, `letterSpacing`) é conferido ao gravar e ao usar; sem tipo o token continua string ou número (um número ainda entra em qualquer campo de comprimento). `collection` opcional dá o nome do grupo. `fontWeight` e `lineHeight` tipados saem sem unidade nas variáveis CSS; os outros números ficam em px. Com `mode`, os valores de um modo de tema (o override tem de combinar com o tipo). `export_code` com `cssVariables: true` escreve `var(--token)` |
| `set_assets` | Assets de imagem do documento (`$nome` → http(s) ou `data:image/`). O `src` de uma image `$nome` precisa bater com um. `null` remove um asset. O export escreve a URL |
| `list_workspaces` / `open_workspace` / `create_workspace` / `import_document` | Lista os workspaces (documentos) do servidor / torna um deles o ativo para todas as ferramentas e para o canvas do humano / cria um vazio / guarda um `.paprika.json` (ex.: do `paprika export --root ID`) como novo workspace sem trocar o ativo. Workspaces arquivados ficam de fora salvo com `includeArchived`; cada linha traz `archived`, `folderId` (vazio na raiz) e `preview` (formas da miniatura ao vivo). A mesma chamada lista `folders`. `import_document` guarda as coordenadas do arquivo (`place` `"none"`); para colocar arte na página atual, use `import_svg`, `import_html` ou `import_image` |
| `rename_workspace` / `archive_workspace` / `unarchive_workspace` / `delete_workspace` | Renomeia um workspace (com desfazer quando é o ativo) / esconde um sem apagar (o ativo passa para o outro não arquivado atualizado mais recentemente; o único não pode ser arquivado; abrir um arquivado desarquiva) / devolve um arquivado à lista sem torná-lo ativo / exclui um de vez, em duas chamadas: sem `confirmToken` nada é apagado e o resultado é um resumo do que se perde (contagens, última edição, capa, qual workspace assume) mais um token de uns dois minutos que pertence àquele workspace; a segunda chamada, com o token, apaga (o ativo passa para o outro atualizado mais recentemente; o único não pode ser excluído) |
| `create_folder` / `rename_folder` / `move_workspace` | Cria uma pasta na visão geral / renomeia uma / move um workspace para uma pasta (`folderId` nulo ou vazio devolve à raiz). Nenhuma delas troca o canvas |
| `list_workspace_ops` | O log de operações de workspace — criar, renomear, abrir, arquivar, desarquivar, excluir e mover, cada um com quem agiu (`user` ou o nome do agente), quando e em qual workspace; a entrada do apagamento guarda o resumo, e as entradas sobrevivem ao workspace que nomeiam |
| `list_pins` / `claim_pin` / `reply_pin` / `resolve_pin` / `wait_for_pins` | Apontamentos: pedidos que o humano deixa no canvas com a ferramenta **Apontar para a IA** (`I`), presos a um nó (`nodeId`, mais a caixa dele em `region`) ou a uma área (só `region`), com `pageId` e o texto. `list_pins` (`status`: `open` (padrão: abertos e em andamento), `claimed`, `resolved`, `all`; `pageId` e `workspaceId` opcionais) devolve a lista com `rev`; `claim_pin {id}` põe o nome e a cor do agente no pino (recusa se outro agente já pegou); `reply_pin {id, text}` acrescenta uma mensagem sem fechar o apontamento; `resolve_pin {id, reply}` fecha e guarda essa resposta como mensagem do agente em `replies` (o fio; `reply` continua sendo o texto mais recente); `wait_for_pins {timeoutMs ≤ 60000, since}` espera até um apontamento aberto mudar depois de `since`. Todo resultado de escrita que traz `version` vem com `openPins: n` (e uma linha de texto) enquanto houver apontamentos abertos no workspace. Os apontamentos ficam numa tabela própria do SQLite: não são nós, não entram no export nem no histórico de desfazer e, no modo time, sincronizam pelo sidecar Loro (mapas de apontamentos e respostas), não como nós do canvas |
| `set_workspace_cover` | Põe uma imagem no card do workspace na página inicial: o screenshot de um frame dele (`rootId`), uma imagem (`image`, base64 ou data URL) ou nenhuma (`clear`). Sem capa o card mostra uma miniatura ao vivo da página, ou a primeira letra quando a página não tem formas |
| `undo` / `redo` / `get_history` | Histórico de um workspace, compartilhado com o humano quando esse workspace é o ativo. `workspaceId` opcional desfaz, refaz ou lê só esse workspace, sem trocar o canvas. Toda ferramenta de escrita aceita `batch`, e várias chamadas com o mesmo batch viram um passo só de undo |
| `lint_design` | Contraste WCAG AA, overflow, tokens inexistentes, texto pequeno, alt, `layout-overflow` (filhos de row/column que saem do frame), `hug-was-meant` (frame de layout no padrão 100×100), geometria (`detached-sibling`, `near-gap` abaixo de 4px, `fully-hidden`), `overlapping-boards` e `covered-by-overlay`. `rootIds` limita a essas subárvores. `groups` dobra cada regra numa contagem e nos primeiros `maxIds` ids (padrão 8), em ordem de severidade. `minSeverity` e `minFontSize` acalmam a lista; `lintIgnore` no nó e `scaledMock` no frame tiram achados intencionais |
| `path_info` | Valida dados de caminho SVG e devolve a caixa exata (com extremos de bezier e arcos), a `origin` do desenho (deslocamento desde a origem do nó), o `d` normalizado e `anchors` (índice plano, subcaminho, posição e alças in/out); com `id` também devolve a caixa no canvas, a origem da transformação e os cantos rotacionados |
| `edit_path` | Move uma âncora de um nó path, ou as alças in/out, com os mesmos helpers do canvas. `index` é o índice plano de `path_info.anchors`; `position` está nesse mesmo espaço de `d`. Um passo de desfazer. Recusa nó travado, cópia dentro de instância e índice depois da última âncora |
| `get_bounds` | Caixas absolutas depois do auto layout (row/column, hug/fill, `wrap`): `x`/`y`/`width`/`height`, `origin` da transformação (centro da caixa) e os quatro cantos após a rotação, no sentido horário a partir do canto superior esquerdo sem rotação, no mesmo sentido do `rotate()` do CSS; `ids` / `rootId` opcionais. Um frame com `layout.wrap` quebra em linhas como o `flex-wrap` do CSS (o mesmo `gap` entre itens e entre linhas), então a altura hug é a soma das linhas. Os `ids` podem estar em páginas diferentes: cada id recebe uma caixa, e o que existe mas não tem caixa (uma página, ou um nó oculto dentro de um frame com auto layout) vem em `unplaced` com o motivo. Sem `ids`, cobre a primeira página (use o id de uma página como `rootId` para outra) e também devolve a caixa do conteúdo da página (a união dos filhos da página, em qualquer página) e o próximo lugar livre |
| `render_screenshot` | PNG de um nó, de uma página ou do canvas. Uma página (ou o canvas) é pintada com o fill da página, branco se não houver; qualquer outra raiz, frame incluído, fica sobre fundo transparente e o PNG tem canal alfa. `path` grava em `<data>/screenshots` (ou `PAPRIKA_SCREENSHOTS`; um caminho fora desse diretório é recusado) e devolve `{path, width, height, url}` com `url` `/api/screenshot/<id>`, no lugar da imagem. Sem `path` a imagem volta como antes, mais `url`. `mode` pinta uma subárvore naquele modo de tema; omitido, a subárvore mantém o modo que herda. `compare` (PNG, JPEG, GIF ou WebP: data URL, base64 cru ou caminho sob `PAPRIKA_IMPORT_DIRS`) é desenhado à direita da captura, na mesma altura, com um vão; largura e altura são da imagem junta e `compare` fica true. `grid` (`true`, ou `{step?, labels?, color?}`) desenha linhas finas a cada `step` unidades do frame (padrão 50, 100, 200 e assim por diante, cerca de 8 a 16 linhas no lado maior) com rótulos de coordenada e uma régua nas bordas superior e esquerda, nas coordenadas da própria raiz (0..largura) e desenhada no PNG, não no documento; `region` `{x, y, width, height}` (unidades do frame) recorta essa parte e `scale` vale para a região, então uma região pequena com `scale` grande amplia (o render é limitado a 4096px por lado antes do recorte). Os dois funcionam com `compare` (valem só para a captura) e com `path`; o resultado informa `grid.step` e `region` (ajustada ao frame). Para ler uma posição, use `region` e `grid` em vez de adivinhar pela imagem. Browser ausente ou incompatível devolve `pnpm --filter @paprika/e2e exec playwright install chromium`. `workspaceId` opcional captura esse workspace sem trocar o canvas |
| `export_image` | PNG, JPEG, WebP, AVIF, PDF vetorial ou SVG (o mesmo SVG vetorial do `export_code` com `format: "svg"`, como bloco de texto; `scale` não se aplica) de um nó/página/canvas. Os formatos raster passam pelo mesmo caminho do Chromium do `render_screenshot`, então batem com ele e com o canvas; sem um Chromium utilizável, voltam a rasterizar o `ExportSVG` do core em Go puro (Inter embutida) e `warnings` avisa. O PDF sempre desenha a geometria do `ExportSVG` em vetores. Fundo como no `render_screenshot`: uma raiz que não é página fica transparente (PNG/WebP/AVIF mantêm o alfa, o JPEG é achatado sobre branco). `workspaceId` opcional exporta esse workspace sem trocar o canvas |
| `import_svg` / `import_html` | Transforma SVG colado (paths, formas, grupos, transforms, `<text>` como nós de texto, sprites `<use>`/`<symbol>`) ou HTML com estilos inline em nós editáveis; imagens, gradientes, máscaras e `<style>` voltam em `warnings`. `import_html` com `computed: true` renderiza o HTML no Chromium do servidor e grava os estilos computados do autor antes de importar; se o Chromium faltar, a chamada falha dizendo como instalar e não cai no caminho de estilo inline. O resultado inclui `ids`, `roots` e `created` no mesmo formato do `create_nodes`, mais uma linha de texto por raiz. As raízes respeitam `place` (`"free"` quando x e y faltam; `"none"` com x/y dentro de um frame row/column põe `layoutPositioning: "absolute"` nas raízes e avisa). `workspaceId` opcional importa nesse workspace sem trocar o canvas |
| `import_image` | Coloca uma imagem raster (PNG, JPEG, WebP, AVIF ou GIF) como nó `image` no tamanho natural do arquivo. `src` é data URL ou caminho local sob `PAPRIKA_IMPORT_DIRS` (padrão: o diretório de trabalho do servidor). Arquivos acima de 3500000 bytes são recusados. Um `.fig` e um PDF são recusados: exporte SVG e use `import_svg`, ou coloque um dos formatos raster. Os bytes originais ficam embutidos, então GIF/WebP/AVIF animados continuam animados no canvas e no HTML (`render_screenshot` captura um frame). Dentro de um frame row/column, `place: "none"` com x/y põe `layoutPositioning: "absolute"` na imagem e avisa. Devolve `ids`, `roots` e `created` no mesmo formato do `create_nodes`, mais uma linha de texto por raiz. Respeita `place` (`"free"` quando x e y faltam). `workspaceId` opcional importa nesse workspace sem trocar o canvas |
| `place_reference` | Coloca o mesmo tipo de imagem como camada travada no fundo de um frame (`frameId`), encaixada dentro dele, a 50% de opacidade salvo se `opacity` for passado. Continua no caminho de pintura de imagem (`locked`, `opacity`, `layoutPositioning: absolute`). `name` padrão é Reference |
| `resize_image` | Reamostra um nó `image` (ou cria um a partir de `src`) para `qhd` 960×540, `hd` 1280×720, `2k` 2560×1440, `4k` 3840×2160, ou `{width,height}`. Go puro (`golang.org/x/image` CatmullRom); sem Chromium. `fit`: `contain` (padrão), `cover`, `fill`. GIF animado → primeiro frame; WebP animado e AVIF recusados. Mesmo formato quando há encoder puro (PNG/JPEG/GIF), senão PNG |
| `analyze_image` | Mede uma imagem de referência antes de redesenhá-la, em Go puro (sem Chromium, uns 50 ms para 1200×900). `src` (data URL, base64 puro ou caminho sob `PAPRIKA_IMPORT_DIRS`; PNG, JPEG, GIF, WebP; AVIF recusado) ou `nodeId` (um nó de imagem). Devolve o tamanho, o fundo (pelas bordas), uma paleta de cores dominantes (`maxColors`, padrão 8; k-means perceptual em OKLab, sem o anti-aliasing) e `blobs`: regiões conexas de uma cor da paleta, da maior para a menor (`minArea` padrão 0,05%, `maxBlobs` padrão 40 com `truncated`). Cada blob traz `bbox`, `centroid`, `areaPx`, `share`, `holes`, `orientation`, `elongation`, `symmetry` (espelho) e `fit`: o melhor entre `circle`, `ellipse` (rotação), `rect`/`roundRect` (raio), `polygon` regular (lados, rotação) ou `freeform` (contorno simplificado, até `maxPoints`), com seu `iou` e um `node` pronto para `create_nodes`. `layout` lista `repeats`, `grids` (linhas, colunas, passo, vão) e `radials` (centro, raio, ângulo do passo). `frame` `{width,height}` devolve coordenadas nesse frame (imagem encaixada e centralizada como em `place_reference`); `region` analisa um retângulo. Determinístico; o texto é um resumo compacto, o `structuredContent` traz tudo |
| `trace_image` | Transforma uma imagem de referência em paths vetoriais editáveis, em Go puro (sem Chromium): use para partir dos contornos reais de uma forma orgânica (uma asa, um monograma, uma baleia) e refinar, em vez de refazê-los à mão. Mesmas entradas de `analyze_image` (`src` ou `nodeId`, `region`, `maxColors`, `minArea`) mais `parentId` (o frame onde desenhar; a imagem é encaixada e centralizada como em `place_reference`; `frame` troca a caixa de encaixe). Cria UM `path` por blob de cor da paleta, preenchimento = a cor do blob, da maior silhueta para a menor para que as formas aninhadas fiquem por cima; o contorno externo e os buracos são subpaths com `fillRule: "evenodd"`, em beziers cúbicas: cantos (giro >= `smoothness`, padrão 50 graus) ficam vivos, o resto é ajustado a até `tolerance` px (padrão 1). Um buraco que outro blob traçado preenche é fechado, um que mostra o fundo fica aberto. A cor de fundo é ignorada salvo `includeBackground` (ponha o fill do frame em `background.color`); `colors` traça um subconjunto da paleta; `group` (padrão true) agrupa os paths; `maxPaths` (padrão 60) limita a quantidade, com `truncated`. Os nós são criados como em `create_nodes` (`normalize: true`, um passo de undo, `batch`, `place`): devolve `ids`, `roots`, `created`, estatísticas por path (`points`, `segments`, `curves`, `lines`, `corners`, `error`), `nodeCount`. `dryRun: true` devolve o `d` de cada path e as estatísticas sem gravar. Determinístico |
| `compare_reference` | Mede um desenho contra a referência, com números, depois de desenhar a partir de uma imagem. `rootId` é o frame; `reference` é data URL, base64 puro, caminho sob `PAPRIKA_IMPORT_DIRS` ou o id de um nó de imagem (por exemplo a camada que o `place_reference` pôs: ela fica fora do render). O frame é renderizado como no `render_screenshot` (`mode`, `scale`) e a referência é ajustada a ele como no `place_reference`. As notas deixam o fundo de fora: cada imagem vira uma máscara de tinta (pixels que diferem do próprio fundo; PNG transparente conta pelo alfa). `iou` (interseção sobre união da tinta), `missing` (tinta da referência não coberta), `extra` (tinta desenhada que não está na referência), `pass` = `iou >= target` (padrão 0.9). `color`: `deltaE` das cores dominantes (OKLab ×100) com participações, `pixelDeltaE` nos pixels em comum, cores desenhadas sem par. `rawPixelMatch` é igualdade pura de pixels, só contexto: o fundo domina (85–97% onde o `iou` é 40–70%). `regions`: as maiores caixas faltando e sobrando em coordenadas do frame (`top`, padrão 8 de cada) com participação e cor. `nodes`: nós que pintam sob `rootId` e saem da referência, do pior ao melhor, com `onReference` e `suggestedMove`. `alignment`: melhor `dx`, `dy`, `scale` globais (e ângulo com `rotation: true`) com `iouBefore` e `iouAfter`; se `significant`, corrija num movimento só antes de tudo. `diff`: PNG (faltando em vermelho, sobrando em azul, coincidente em cinza) guardado como um screenshot (`url` `/api/screenshot/<id>`; `path` também grava sob o diretório de screenshots; `includeDiff` devolve inline). As últimas notas por workspace e raiz ficam na memória: `previous`, `delta` e `sameReference` dizem se a rodada melhorou. Determinístico; precisa do Chromium. O texto é um resumo compacto |
| `fit_to_reference` | Ajusta os números de nós que você já desenhou para o frame bater com a referência: desenhe a estrutura, depois use esta, depois o `compare_reference`. `rootId` é o frame, `ids` os nós a ajustar (dentro dele; `rect`, `ellipse`, `path` e `frame`), `reference` como no `compare_reference`. `params` (padrão `position` e `size`): `position`, `size`, `rotation` (graus, mantida em -180..180), `radius` (cantos de rect e frame) e `pathPoints` (âncoras de um path, com as alças junto; só as `maxAnchors`, padrão 8, de maior erro local se movem; paths com `viewBox` não são editados). Maximiza o IoU da tinta do frame contra a referência (as máscaras do `compare_reference`; as cores ficam como estão) por descida de coordenadas com passo decrescente, os nós com mais erro primeiro, até `maxIterations` rodadas (padrão 60) ou até a máscara chegar a `target` (padrão 0.99). O frame é renderizado no Chromium uma vez como está e outra sem os nós ajustados; os nós ajustados são rasterizados em software (rects, rects arredondados, elipses, paths com regra de preenchimento, traços, rotação, deslocamentos de grupo e frame) nessa máscara, então não há screenshot por tentativa (uns 20 nós em menos de 5 s). Os números são arredondados para inteiros ou meios quando isso não custa nada. Grava uma transação `update_nodes` (um passo de undo; `batch` e `label` valem) a menos que `dryRun`, e só quando o render do Chromium com os números novos não é pior que o de antes. Nós em layout de linha/coluna mantêm a posição, tamanhos hug/fill não são ajustados, e nós travados, ocultos, texto e outros tipos são pulados com o motivo. Devolve por nó `changes` (antes/depois) e `pathPoints` movidos, `iou.mask` e `iou.chromium` (antes/depois; diferença acima de 0.03 vira aviso: texto, sombras, degradês e tinta sobreposta não são modelados), `applied`, `pass` (IoU do Chromium depois >= `target`), `iterations` e o tempo. Determinístico; precisa do Chromium |
| `export_code` | HTML autocontido, componente React (TSX), SVG vetorial (caixas do `layout(doc)` do core, sem Chromium headless), componente React com classes utilitárias do Tailwind (`tailwind`), HTML autocontido com classes do Tailwind (`tailwind-html`), componente React mais o seu `.module.css` (`css-modules`: dois blocos de texto, o `.tsx` primeiro e a folha de estilo depois), componente Angular standalone (`angular`: três blocos — `.ts`, template, `.css`) ou componente Svelte num arquivo só (`svelte`); `cssVariables: true` escreve os tokens como `var(--nome)`, com uma regra por modo de tema |

Camada de agentes:
- Os argumentos são estritos: um argumento desconhecido no topo (`render_screenshot {id}`, `lint_design {ids}`) é um erro que lista os argumentos válidos e sugere o provável (`rootId`, `rootIds`), em vez de ser descartado e agir no canvas inteiro. O `inputSchema` de toda ferramenta diz `additionalProperties: false`.
- O guia, as descrições das ferramentas, os erros, os avisos e as mensagens do lint são em inglês (o guia também em português, ver acima).
- As ferramentas que respondem JSON declaram `outputSchema` e devolvem `structuredContent`; o bloco de texto continua com o mesmo JSON (no `get_nodes` e no `get_history`, o array puro; no `analyze_image`, no `compare_reference` e no `fit_to_reference`, um resumo compacto). `create_nodes`, `duplicate_nodes` e as ferramentas de importação também acrescentam uma linha legível por raiz.
- As ferramentas de documento aceitam `workspaceId` opcional (outline, nós, bounds, criar/atualizar/apagar/mover/agrupar, tokens, lint, screenshot, export, importações, undo/redo e as outras escritas de documento). Sem ele, vale o workspace ativo, que é o canvas do humano. Com ele, a ferramenta lê ou escreve esse workspace sem `open_workspace` e sem mover o canvas. A primeira linha do outline e todo resultado de escrita trazem `workspaceId` e `workspaceName`. Cada workspace guarda o próprio histórico enquanto o processo estiver no ar. Um id desconhecido é um erro que lista os workspaces.
- O histórico identifica o agente pelo `clientInfo.name` do MCP (`agent:claude-code`). No HTTP o servidor é stateless, então o `initialize` devolve um `Mcp-Session-Id` que só guarda esse nome; sem ele, vale o User-Agent, como antes.
- O canvas aberto informa como pinta no WebSocket: `{type:"hello", renderer:"wasm"|"dom"}`, de novo quando o humano troca o renderizador. O servidor responde com o mesmo hello. O `get_document_outline` lista um valor por aba conectada, ou `none` quando não há aba. Os screenshots continuam no caminho HTML.

## Formato do documento

```jsonc
{
  "format": "paprika/1",
  "name": "Demo",
  "tokens": { "brand": "#c43d27", "text.md": 16 },
  "rootIds": ["login"],
  "nodes": {
    "login": { "type": "frame", "id": "login", "parentId": null, "width": 390, "height": 760,
               "layout": { "mode": "column", "gap": 20, "padding": 24 }, "children": ["t1"] },
    "t1": { "type": "text", "id": "t1", "parentId": "login", "text": "Olá", "color": "$brand",
            "width": "fill", "height": "hug" }
  }
}
```

Tipos: `frame` (contêiner com pintura e layout livre, linha ou coluna), `group` (agrupa sem pintar; a caixa segue os filhos), `frame` com `component: true` (componente) ou `instanceOf` (instância: os filhos são cópias geradas do componente, escaladas por `scale`, com `overrides`), `page` (canvas separado no arquivo; com páginas, todo nó de topo é página e os frames ficam dentro delas), `rect`, `ellipse`, `text`, `image`, `path` (forma vetorial com dados de caminho SVG: retas, curvas bezier cúbicas e quadráticas, arcos; `fill`, `stroke`, `fillRule`, `strokeCap`, `strokeJoin` e `viewBox` opcional para escalar um grid de ícone).
Um nó de texto pode ter `runs`: até 200 trechos `{ start, end }` em índices UTF-16, ordenados e sem sobreposição (encostar pode). Cada trecho precisa de ao menos um entre `fontWeight` (100–900 ou `$token`), `color`, `fontSize` (número ou `$token`), `italic: true` ou `href` (`http(s)`, `mailto`, ou caminho que começa com `/` ou `#`). `create_nodes` e `update_nodes` carregam `runs`; `null` no update apaga. A exportação HTML, React, SVG, PNG e PDF preserva os trechos. Uma cópia dentro de uma instância pode sobrescrever `runs` junto com fill, color, text, src, alt, visible e opacity.
`stroke` é `{ color, width, style?, position? }` com `style` `solid`|`dashed`|`dotted` (traço a partir da espessura; omitir = sólido) e `position` `inside`|`center`|`outside` (omitir = dentro em caixas/formas, centro em paths).
`gradient` é opcional em `frame`, `rect`, `ellipse`, `text`, `image`, `path`, `shape` e `page`: `{ type: "linear"|"radial"|"conic", angle?, cx?, cy?, radius?, stops }`. `stops` tem de 2 a 12 `{ color, offset }` com `offset` em 0..1. `angle` omitido vale 180 (CSS: 0 é para cima, 90 é para a direita), `cx`/`cy` valem 0.5 e `radius` vale 0.5 (0..2). Com `gradient`, ele ganha do `fill`. `null` no update remove. Uma string de gradiente CSS ou `url()` em `fill` ou em qualquer `color` é recusada no create/update (pintava preto em paths): o erro aponta para `gradient`, p. ex. `{ type: "linear", angle: 90, stops: [{ color: "#fff", offset: 0 }, { color: "#000", offset: 1 }] }`.
Em `frame`, `rect` e `image`, `radius` é um comprimento ou `[tl, tr, br, bl]` (superior esquerdo, superior direito, inferior direito, inferior esquerdo). Cada canto é um número ou um `$token`, como gap e padding. Um valor mantém os cantos ligados; o inspector alterna esse vínculo. Os outros nós continuam com um raio só.
Tamanhos: número, `"hug"` (conteúdo) ou `"fill"` (ocupa o espaço do pai); `width`/`height` não aceitam `$token` (tokens valem para padding, gap, radius, espessura do traço...). `layout.padding` é um valor, `[vertical, horizontal]` ou `[topo, direita, baixo, esquerda]` (ordem do CSS; dois valores são gravados como quatro); outros tamanhos são recusados com as formas aceitas. `lineHeight` é um multiplicador do `fontSize` (1.4), não pixels: para uma linha de 22px em texto de 16px use 1.375; valores acima de 10 são recusados com essa dica. Um filho de um frame em linha/coluna pode definir `layoutPositioning` como `"absolute"` (omitir ou `"auto"` fica no fluxo): ele mantém `x`/`y` relativos ao pai e sai do fluxo, do gap e do hug. `create_nodes` e `update_nodes` aceitam o campo; `null` no update remove. Um filho fora do fluxo pode definir `constraints` como `{ horizontal: left|right|center|scale, vertical: top|bottom|center|scale }` (omitir = left e top). Quando a largura ou a altura do frame pai muda (um tamanho numérico, ou o tamanho calculado de um frame `fill`/`hug`, então um ancestral redimensionado alcança frames fill aninhados), esses filhos mantêm a borda left/top, a margem right/bottom, o centro, ou escalam com o pai. Filhos no fluxo ignoram o campo. `null` no update remove. Detalhes em [docs/pt-BR/arquitetura.md](arquitetura.md). O trabalho planejado está em [docs/pt-BR/backlog.md](backlog.md).

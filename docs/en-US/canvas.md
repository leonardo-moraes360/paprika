# Using the canvas

Everything you can do by hand in the browser: workspaces, tools, shortcuts, diagrams and how agents show up. Back to the [README](../../README.md).

## Workspaces and tools

Workspaces: `http://127.0.0.1:4777` opens on the workspace overview: one click selects a card, a double click (or Enter) opens that workspace's canvas at `/w/<id>`, a double click on the name (or F2) renames it, the picture button (or dropping an image on the card) sets its cover image, and the trash button (or Delete) deletes it after a confirmation; without a cover the card shows the first letter of the name; the Paprika logo goes back. A workspace is one document of the database. The server has one active workspace, shared by the canvas and the MCP agents: picking a card on the overview or calling `open_workspace` switches it for everyone, but loading `/w/<id>` (a link, a reload, a new tab) only views that workspace: the tab points its WebSocket at it (`{"type":"view","workspaceId"}`), edits and undo from that tab go to that workspace, and the active workspace does not change. A tab does not follow an agent that switches the active workspace; the overview does. HTTP: `GET /api/workspaces`, `POST /api/workspaces` (`{ "name" }`), `POST /api/workspaces/<id>/open`, `PATCH /api/workspaces/<id>` (`{ "name" }`), `DELETE /api/workspaces/<id>` (409 for the only workspace), `GET`/`PUT`/`DELETE /api/workspaces/<id>/cover` (PUT takes the raw PNG, JPEG, WebP or GIF, at most 2 MiB; never SVG).

Shortcuts: `V` select, `I` point for the AI (pins), `F` frame, `R` rectangle, `O` ellipse, `T` text, `P` pen (click = corner point, click and drag = bezier handles, click the first point to close, `Enter`/`Esc`/double-click to finish an open path, `Backspace` removes the last point), `Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z` (your own steps), `Ctrl+H` history, `Ctrl+D` duplicate, `Delete`, arrows (Shift = 10px), `Esc` selects the parent, `Enter` selects the direct children, `Tab` / `Shift+Tab` cycle siblings.
Undo per author: `Ctrl+Z` (and the toolbar Undo button) undoes the latest applied step of the human of this tab, never an agent's; `Ctrl+Y` / `Ctrl+Shift+Z` redo the last step this tab undid. A toast (one at a time, about 6 s, paused while hovered or focused, `role="status"`) says what happened: "Undone: <step>" with **Redo**; "Undone your step: <step>. N newer steps by agents were kept." when agents wrote after you; "Nothing of yours to undo. The latest steps are by <agent>." with **View history** when every step belongs to someone else; and "Can't undo only this step: newer steps changed the same elements." when the selective undo is not safe (nothing is changed). `Ctrl+H` (or the toolbar menu, or **View history**) opens the History panel: all steps (at most 500) grouped by author, newest first, with the undone ones marked "undone", a filter **All** / **Only mine**, a click that selects the step's nodes on the canvas, and a per-step menu (**Undo this step**, **Redo this step**, **Select the step's nodes**, **Copy label**). Undoing an agent's step asks for confirmation (destructive alert dialog); your own steps undo directly.
How it works: every history step records who made it (`actor`) and a footprint of what it touched (node ids, the child lists it changed, layout and component coupling), computed from the step's inverse and kept with the persisted history (`history.meta`). Undoing a step that is not the newest is a selective undo: it applies that step's stored inverse on top of the current document, as one normal write (version bump, WebSocket delta, persistence), and only when no newer, still-applied step has a footprint that overlaps it (and the inverse still applies); otherwise nothing is written and the result is `conflict`. The undone step moves to the redo list with the author who undid it; redo is checked the same way (no overlapping step applied since, and the pending redos above it first). A new write clears only the redo of the author who wrote. `Ctrl+Z` is `{"type":"undo","mode":"own"}` over the WebSocket and the panel uses `{"type":"undo"|"redo","mode":"step","step":<id>}`; both answer with an `ack` carrying `step` (`result` is `undone`, `redone`, `nothing`, `conflict` or `missing`, plus `label`, `actor`, `newer`, `withActor`). `GET /api/workspaces/<id>/history` returns the panel feed. MCP `undo` / `redo` and the plain WebSocket `undo` / `redo` keep their linear behavior (the newest step of any author), now with the same conflict check on redo. Changes that arrive from a team peer are not history steps, so a selective undo does not see them.
Layer order (Z): `Page Up` brings forward one step, `Page Down` sends backward one step, `Ctrl+Page Up` (or `Cmd+Page Up`) brings to front, `Ctrl+Page Down` (or `Cmd+Page Down`) sends to back — same `index` directives as MCP (`forward` / `backward` / `front` / `back`), one undo step. The inspector's **Ordem** section has the four actions with those shortcuts in the button titles. Shortcuts do not fire while focus is in an input, textarea, select or contenteditable.
Selection: `Shift`-click (canvas or layers) adds or removes a node, and so does `Cmd`-click. `Ctrl`-click selects the node under the cursor, through groups and instances. Dragging on empty canvas draws a selection box, `Ctrl+A` selects the siblings (or the whole page), `Ctrl+G` groups the selection, `Ctrl+Shift+G` ungroups, `Ctrl+Alt+G` (`Cmd+Alt+G` on macOS) wraps the selection in a frame. The multi-selection inspector aligns (`left` / `center` / `right` / `top` / `middle` / `bottom`) and distributes (horizontal / vertical, 3 or more) in one undo step each. Each layer row can hide or lock that node; **Show all** and **Unlock all** in the layers panel apply to the current page, also one undo step each. A click inside a group selects the group; double-click selects the node under the cursor. `Enter` selects the direct children of the selected frames and groups; when the selection has no children, `Enter` still arms pan. `Tab` and `Shift+Tab` move to the next and previous sibling. Right-click lists the layers under the cursor, front to back, and choosing a row selects that node. These shortcuts stay quiet while typing or while a control has keyboard focus. Dragging, arrows, `Delete` and `Ctrl+D` act on the whole selection.
Center content: a frame with children (text, icon or image) shows a **Content** section in the inspector with a one-line summary of the children, two icon toggle groups (Horizontal: left, center, right; Vertical: top, middle, bottom) and a **Center** button. The control edits the frame's auto-layout, the same one the **Layout auto** section shows: **Center** turns on a row layout (a column layout stays a column) with `justify` and `align` set to `center`, padding 0 and the gap kept, so the children enter the flow and stop using their own x and y; each toggle group changes one axis and keeps the other (in a row, Horizontal is `justify` and Vertical is `align`; in a column it is the other way around); no toggle is active while the children are placed by hand or the layout uses `stretch` or `between`. `Alt+C` on the canvas, the **Center content** item of the right-click menu and the button do the same for every selected frame in one undo step (`Alt+C` and the menu item undo the centering by removing the auto-layout when every selected frame is already centered). A rect or ellipse cannot hold children in the model, so when text, icons or images are drawn over one (siblings above it, fully inside its bounds, visible and unlocked, up to 64 siblings scanned; a circle for an ellipse; not rotated, not in an auto-layout parent, not part of an instance) the same section works on it: the shape becomes a frame in place (same id, geometry, fill, stroke, radius, effects and z-order; an ellipse becomes a frame with `radius` half its size), adopts that content without moving it, and gets the centered layout, all in one undo step that restores the original rect or ellipse. A shape with nothing over it only shows the hint to add a text or icon; a frame with no children does not show the section.
Drag and drop: dragging a node over a frame or group reparents it on drop (`move` through `applyOps`, one undo). Inside an auto-layout frame the drop point picks the child index and an insertion marker follows the pointer; auto-layout children are draggable. Layers panel rows drag to reorder siblings or drop onto a container to reparent. Dropping PNG/JPEG/WebP/AVIF/GIF, SVG or HTML files from the OS onto the canvas imports them at the drop point (images as `image` nodes with a data URI; SVG/HTML via the same importers as paste).
Resize: the selection shows four corner handles; dragging one keeps the opposite corner fixed. Hold `Shift` while dragging to keep the current aspect ratio (the axis with the larger delta leads; the other follows). Hold `Shift+Alt` to lock a 1:1 square. A small hint under the size badge names the active lock (`Proporção · Shift` or `1:1 · Shift+Alt`). Each resize is one undo step. When the node is rotated, the outline, the corner handles and the rotate handle sit on that rotated box (the same corners as `get_bounds`), and a corner drag stays in the node's own axes so the opposite corner does not move. The rotate handle sits just outside the top edge; `Shift` snaps the angle to 15°. A marquee selects a rotated node only when the rectangle touches that rotated box.
Spacing: a selected auto-layout frame (row or column) shows a bar on each padding edge and one in each gap between flowing children, including the gap between wrapped lines. Drag a padding bar to change that side; when the four sides differ, `padding` is stored as top, right, bottom, left. Hold `Alt` to set every side to the value of the side you are dragging. Drag a gap bar along the flow to change `layout.gap` (the same value on the main axis and between wrapped lines). The flex layout previews while the pointer is down and the release is one undo step. A click that does not move does not write. Locked frames, instances and component copies do not show the bars. The bars follow that frame's rotation.

Drag a padding bar to change that side; when the four sides differ, `padding` is stored as top, right, bottom, left. Hold `Alt` to set every side to the value of the side you are dragging. Drag a gap bar along the flow to change `layout.gap` (the same value on the main axis and between wrapped lines). The flex layout previews while the pointer is down and the release is one undo step. A click that does not move does not write. Locked frames, instances and component copies do not show the bars. The bars follow that frame's rotation.

Components: "Make component" in the inspector of a frame, then "New instance". A click inside an instance selects the instance; select a copy in the layers (or double-click it) to override its text, colors, opacity or visibility. Changes to the component reach every instance; "Detach" turns an instance into plain nodes.
Theme modes: the inspector's document panel lists the tokens of each mode and adds one with `dark: bg = #14161f`; "Theme mode" on a frame or page applies a mode to everything inside it.
Diagrams: `S` box, `D` diamond (decision), `G` triangle, `C` cylinder, `B` parallelogram, `U` cloud, `N` sticky note, `A` arrow. A click creates a shape at its default size (or drag to size it) and starts editing its text; double-click a shape to edit the text again (`Enter` adds a line, `Esc`, `Ctrl+Enter` or clicking away confirms). With the arrow tool, drag from one shape to another: both ends stick to the shapes and the arrow follows them when they move (an end dropped on empty canvas stays at that point). A selected arrow shows a handle on each end: drag it onto a shape to attach, or onto empty canvas to detach (one undo step). Deleting a shape deletes its arrows; the inspector gives an arrow a label ("yes", "no", drawn halfway along it in the stroke color), switches it between elbow and straight, picks the side of each end, the arrowheads and dashes.
Color fields: the swatch opens a custom picker (saturation/value plane, hue and alpha, hex and RGB). The pipette uses the EyeDropper API when the browser has it; otherwise the next click on the canvas reads the color of the node under the pointer. Document color tokens appear as swatches and write `$token`; recent colors are remembered in the browser. Alpha below 1 commits `rgba(...)`. Enter or Space opens the picker from the swatch, arrow keys move the active control, Escape closes it and returns focus to the swatch.
Font family (text nodes): the inspector **Fonte** field is a combobox (`FontPicker`) with common stacks, families already used in the document, and optional system fonts. Opening the list never queries the OS; **Usar fontes do sistema…** calls the Local Font Access API (`queryLocalFonts`) on demand when the browser supports it. Each row previews in its own face; typing a name that is not in the list and choosing **Usar “…”** (or Enter) still commits a custom `fontFamily` string.
Double-click a text node to edit it on the canvas. The toolbar applies bold, italic, size, color and a link to the selection; Enter inserts a line break, and Escape or Ctrl/Cmd+Enter commits `text` and `runs`. Replacing the whole string in the inspector clears `runs`. The canvas paints the same spans as HTML export.
Diagrams: `S` box, `D` diamond (decision), `G` triangle, `C` cylinder, `B` parallelogram, `U` cloud, `N` sticky note, `A` arrow. A click creates a shape at its default size (or drag to size it) and starts editing its text; double-click a shape to edit the text again (`Enter` adds a line, `Esc`, `Ctrl+Enter` or clicking away confirms). With the arrow tool, drag from one shape to another: both ends stick to the shapes and the arrow follows them when they move (an end dropped on empty canvas stays at that point). A selected arrow shows a handle on each end: drag it onto a shape to attach, or onto empty canvas to detach (one undo step). Deleting a shape deletes its arrows; the inspector gives an arrow a label ("yes", "no", drawn halfway along it in the stroke color), switches it between elbow and straight, picks the side of each end, the arrowheads and dashes.
Point editing: double-click a path to edit its points. Drag a point (its handles come along) or a handle (the opposite handle mirrors it; hold `Alt` to move it alone). Double-click a point to switch between corner and smooth, double-click the outline to add a point, `Delete` removes the selected point, `Esc` or `Enter` finish. Each gesture is one undo step. Quadratic curves and arcs become cubic curves once you edit them.
Paste and export: `Ctrl+V` with SVG markup, HTML (e.g. copied from a web page) or a raster image (PNG, JPEG, WebP, AVIF, GIF) in the clipboard creates editable nodes inside the selected frame, or on the page at the center of the view. An image becomes an `image` node whose `src` is a `data:image/` URI (the same path as `import_image`); `.fig` and PDF are refused. The `⇩` toolbar button downloads the selection (or the current page) as SVG.
Toolbar dock: drag the grip on the floating toolbar to the left, top, right or bottom edge of the canvas (left/right lay the tools out vertically), or pick the side in the toolbar's `⋯` menu. The choice is remembered in this browser (`paprika.toolbar.dock`). When a side panel is collapsed into its floating button (see above), that button moves past the toolbar so the two never overlap.
Pages: the "Pages" / "Páginas" panel on the left switches pages, `+` adds one (the first `+` turns the current canvas into "Page 1" / "Página 1" in the UI language), double-click renames, `×` deletes (undoable). The language control in the top bar (and browser language on first visit) picks English or Brazilian Portuguese; the choice is kept in `localStorage` (`paprika.locale`).
Renaming: double-click a layer in the "Camadas" panel or a frame title on the canvas to rename it in place. `Enter` or clicking away confirms, `Esc` cancels; each rename is one undo step. Instance copies take their name from the component.
Navigation: scroll = pan, `Ctrl`+scroll = zoom, hold `Space` and drag = pan (the cursor turns into a hand). Hold `Enter` and drag does the same, unless the selection has children: then `Enter` selects those children instead of arming pan.
Agent edits flash on the canvas and show up under "Atividade" (activity): each row shows the actor (color dot and name), the action, a relative time, batch grouping for consecutive edits by the same actor, and an "agora" marker for the undo/redo position; long labels truncate with the full text in `aria-label`.
Agent presence: every agent connected over MCP gets its own cursor, name and color on the canvas, like a multiplayer session. Each tool call (reads too) moves the cursor to the nodes it acted on, outlines them and labels what the agent is doing; the list at the top right shows who is in the document. Two sessions of the same client get distinct names ("claude-code", "claude-code 2"). Presence is not saved: an idle agent fades after 15 s and disappears after 2 minutes. Nodes an agent creates appear at once in their final form, in the DOM and on the WASM layer; only the agent's outline walks them in tree order to show what it built, and the whole walk takes about 2 s at most per write (a long queue is walked faster, skipping some nodes). Two agents writing at the same time each get their own walk. With `prefers-reduced-motion` there is no walk, only the final state.
Pins for the AI: `I` (or the crosshair button in the toolbar) is **Point for the AI**. Click an element to pin it, or drag to mark an area, then write what an agent should do there in the box that opens next to the pin (`Ctrl+Enter` sends, `Esc` cancels). Open pins show on the canvas with a number (red outline; dashed for an area); when an agent takes one with `claim_pin` the pin turns its color and shows its name, and `resolve_pin` takes it off the canvas. `Shift+I` (or the chip in the top bar) opens the **Pins** panel: open and resolved pins, the thread (human and agent replies), "Show on canvas", reopen, mark resolved and delete. The composer on the pin and in the panel appends a reply. Pins are not part of the design: they are not exported and not in the undo history. HTTP: `GET /api/pins` (`?workspaceId=`, `?status=`), `POST /api/pins` (`{region, text, nodeId?, pageId?, workspaceId?}`), `PATCH /api/pins/<id>` (`{status: "open" | "resolved"}` or `{text}`), `POST /api/pins/<id>/replies` (`{text}`), `DELETE /api/pins/<id>`; the WebSocket sends `{type:"pins", rev}` when they change.

## Renderer: DOM or WASM

The button at the right of the zoom pill switches how shapes are drawn ([ADR 0002](adr/0002-canvas-renderer-rust-wasm.md)):

- **DOM** (default): every node is an HTML element styled by `nodeStyle`, the same engine as the screenshot and the export.
- **WASM**: frames, rectangles, ellipses and paths are drawn by `crates/render` (Rust, [vello](https://github.com/linebender/vello)) on a `<canvas>` under the DOM. It uses **WebGPU** when the browser has a hardware adapter (the button reads `GPU`) and falls back to **vello_cpu** otherwise (`CPU`), including when only a software WebGPU adapter exists. Text, images, selection and hit testing stay in the DOM.

A selected node with a structured `gradient` shows handles for the angle, the center, the radius and each stop, while the node is not rotated. The same object is what `nodeStyle` paints, so the canvas, the screenshot and the export stay identical.

The choice is saved in the browser; `?renderer=wasm` or `?renderer=dom` in the URL overrides it. Nodes the WASM layer cannot draw exactly (structured gradients, `oklch()` / `color-mix()` / Display P3 and other non-solid colors, a shadow on a path, more than one shadow, an inner shadow, an outline, or a filter / backdrop filter) keep their DOM paint. One outer shadow on a frame, rectangle or ellipse is still drawn by WASM. Known difference: text and images always sit above WASM-drawn shapes, even when a shape comes later in the layer order. Screenshots and exports are unchanged (HTML).

A node stays on the DOM when any of these rules holds (`WASM_FALLBACK_RULES` in `packages/core/src/displayList.ts`, one case each in `packages/core/test/wasmPaintable.test.ts`):

| Rule | Why |
| --- | --- |
| Not a frame, rectangle, ellipse or path | Text, images, groups, connectors and `shape` nodes are DOM |
| Uneven corner radii, or under a frame with them | The renderer takes one radius |
| Under a rotated ancestor | The display list rotates a box about its own centre only |
| Gradient, or a fill / stroke / shadow color that is not a classic solid | Gradients, `oklch()`, `color-mix()`, Display P3 |
| Outline, filter or backdrop filter | CSS only |
| More than one shadow, an inner shadow, or any shadow on a path | One outer shadow on a frame, rectangle or ellipse is drawn by WASM |
| Dashed or dotted stroke | CSS only |
| Stroke position other than inside (center for paths) | WASM strokes inside, and paths on the centre line |

Positions come from the DOM layout, not from the document: `measureBoxes` reads each node's exact fractional box (`getBoundingClientRect` relative to the world, divided by the zoom, in 1/64 px units like the layout engine), so ancestor borders and fractional auto-layout sizes are included; rotated nodes use their centre and own size, and their descendants chain through the offsets. `wasm.e2e` asserts that every box is within 0.1 px of the DOM layout on a fixture with nested inside strokes, fractional padding and gaps, rotation and a clipped frame, and compares it pixel by pixel with the DOM.

Stroke widths on paths are in viewBox units in every renderer (DOM, WASM, screenshot and export): when a path's box differs from its `viewBox`, the stroke scales with the geometry, so `stroke.width: 10` on a 20×20 box over a `0 0 100 100` viewBox is 2 px. The WASM renderer multiplies the width by the same `min(w/vw, h/vh)` it applies to the points, and the paint-order overlap check uses the scaled width. `wasm.e2e` covers box ≠ viewBox (small, large and thin strokes) pixel by pixel against the DOM; it runs in CI on any change to `crates/render`, `packages/core`, `web-legacy` or `packages/e2e`.

The WASM renderer is built by `pnpm build` when Rust is installed (`rustup target add wasm32-unknown-unknown` and `cargo install wasm-bindgen-cli --version 0.2.130`); without it the build prints a warning and the button stays disabled. `PAPRIKA_REQUIRE_WASM=1` turns that warning into an error.

`shadow` is one object or a list of up to 8 `{x, y, blur, spread, color, inner?}`. `inner` paints `inset` on the box. A path or shape keeps outer shadows as `drop-shadow()` and paints an inner shadow as an inset box, because CSS `drop-shadow` has no inset; SVG warns and skips the inner layer, and still ignores spread. `outline` is `{color, width, style?, offset?}`. When the stroke already uses the CSS outline (center or outside), the outline field is a solid ring on `box-shadow` so both stay visible. `filter` and `backdropFilter` are `{blur?, saturate?, grayscale?, brightness?, sepia?, invert?, hueRotate?}`; an empty object is refused. The inspector section Efeitos edits all four.

# AGENTS

## Map

- `packages/core`: model (zod), `applyOps`, `History`, `nodeStyle`, render/export, lint, outline. No I/O.
- `server`: the only server (Go + SQLite): MCP (stdio and HTTP `/mcp`), HTTP/WS, screenshot (chromedp), CLI `paprika`. `server/internal/core` is a port of `packages/core`, held to it by fixtures; `server/contract/mcp.json` is the MCP contract (tool definitions, served verbatim).
- `packages/e2e`: black-box suites against the Go binary: `test:api` (MCP over HTTP and stdio, HTTP API, WebSocket) and `test:e2e` (canvas in Playwright, including the WASM renderer).
- `web-legacy`: the app in use, served by the Go server: React + Vite canvas. The open document comes over WebSocket into an external store (`useDocument.ts`: `liveStore`, read with `useLive(selector)` so each component re-renders only for its slice; presence goes to `AgentCursors` and the team panel, not the editor); HTTP data (workspace list and its mutations) goes through TanStack Query (`src/api.ts`, `src/workspaces.ts`), and the WebSocket only invalidates those queries. `wasmLayer.ts` runs the optional WASM renderer. Styling is Tailwind CSS v4 without Preflight ([ADR 0003](docs/en-US/adr/0003-tailwind-css.md)): theme tokens in `src/styles.css`, shared class lists in `src/ui.ts`, and the copied shadcn primitives in `src/components/ui/` on the `ui-*` semantic tokens ([ADR 0005](docs/en-US/adr/0005-shadcn-ui.md)) — new UI code uses the primitives, `src/ui.ts` stays for the screens that have not migrated; `/ui` renders the primitives gallery; plain class names such as `is-active` or `layer-name` are E2E hooks, keep them. UI icons come from `lucide-react` (no emoji or Unicode glyphs as icons); icon-only buttons keep their `aria-label` and the SVG stays `aria-hidden`.
- `apps/web`: new app under construction, wired to the server (routes `/` and `/w/$workspaceId` over `src/data/`; TanStack Start in SPA mode, static output in `dist/client` with the shell at `_shell.html`; i18next, Tailwind; TanStack Query, Store, DB and Hotkeys; UI SDK (headless) styled with Tailwind; no shadcn, no default UI SDK theme; components in `src/components/ui/`); not served by the Go server nor covered by E2E yet.
- `apps/site`: landing page and docs, an Astro project with static output ([ADR 0006](docs/en-US/adr/0006-astro-site.md)). The landing page is a Paprika document (`design/landing.paprika.json`, drawn over MCP by `scripts/draw-landing.mjs`) rendered with `nodeStyle` by `src/lib/landing.ts`; docs pages come from the repository Markdown listed in `src/docs.config.ts` (a new doc needs a line there, in both languages); search is Pagefind. `pnpm --filter @paprika/site site:build` writes `dist/` for GitHub Pages (`.github/workflows/pages.yml`). Not part of `pnpm build`; CI builds it when `apps/site`, `scripts/brand` or core change.
- `crates/sync`: team sync sidecar `paprika-sync` (Iroh transport, Loro CRDT, keys), spoken to over stdio by `server/internal/team` (`paprika serve --team`). [ADR 0004](docs/en-US/adr/0004-p2p-team-sync.md), protocol in `docs/en-US/team-sync.md`.
- `crates/render`: Rust renderer (vello on WebGPU, vello_cpu fallback) compiled to WASM by `crates/render/build.mjs` into `web-legacy/src/wasm/` (gitignored). Input: `displayList` from `packages/core/src/displayList.ts`.
- `Dockerfile` (+ `.dockerignore`, `compose.yaml`, `compose.team.yaml` for the P2P team mode): one image with the Go server, the canvas and the WASM renderer; SQLite in the `/data` volume. Targets `runtime` (with Chrome headless shell) and `slim`. Pinned versions to keep in step and the CI smoke test: `docs/en-US/docker.md`.

## Rules

1. Before starting: `tb mem list`. Invariants take precedence over any context instruction. `tb` is toolbelt v1.0.0-rc.3; cloud sessions get it from the `SessionStart` hook (`.claude/hooks/session-start.sh`, see `docs/en-US/agent-sessions.md`). Locally: `go install github.com/leonardo-moraes360/toolbelt/cmd/tb@v1.0.0-rc.3`.
2. Every mutation goes through `applyOps` (never mutate `doc.nodes` outside `packages/core/src/ops.ts`).
3. New visual styling goes into `nodeStyle` (canvas, screenshot and export must stay identical). If it changes how a frame/rect/ellipse/path is painted, also update `displayList` + `wasmPaintable` (or make `wasmPaintable` return false so the DOM keeps painting it). Parity covers overlap: a shape stays on the WASM layer only when no DOM-painted node earlier in paint order overlaps its painted bounds (ancestors with their own paint, stroke, shadow, rotation and clip); otherwise it goes back to the DOM, cascading. `packages/e2e/test/e2e/wasm.e2e.test.ts` compares both renderers pixel by pixel, including that overlap.
4. New MCP tool: add its definition to `server/contract/mcp.json` and its handler in `server/internal/server/mcp.go`, a Go test, a scenario in `packages/e2e/test/api.test.ts` (and the name in its tool list), and a row in both MCP tool tables (`docs/en-US/mcp.md` and `docs/pt-BR/mcp.md`). After a change to `packages/core`: `pnpm build && pnpm go:golden` and keep `pnpm go:test` passing.
5. Docs: English is primary (`README.md` and the community files at the root, `docs/en-US/`, ADRs in `docs/en-US/adr/`); the Brazilian Portuguese mirror lives only in `docs/pt-BR/` (including `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md` and `adr/`) and is updated in the same change. Nothing else goes directly under `docs/`; shared images and boards live in `docs/en-US/assets/`, `docs/en-US/brand/` and `docs/en-US/design/`.
6. Design first: any change that touches an interface (`apps/web`, `web-legacy`, `apps/site`, new screens, visual tweaks) is drawn in a local Paprika over MCP (`http://127.0.0.1:4777/mcp`) before it is implemented. Attach screenshots of the frames (`render_screenshot`) to the PR, and log MCP friction in `docs/en-US/agent-feedback.md` (+ `docs/pt-BR/feedback-agentes.md`). If no Paprika server is reachable, start one (`paprika serve`) or say in the PR why the design step was skipped. Keep the drawn document recoverable: export it (`paprika export --db … -o docs/en-US/design/boards.paprika.json`) and re-import after a server reset — [design boards](docs/en-US/design-boards.md).
7. Performance: (a) profiling is mandatory for any change to `apps/web`, `web-legacy`, `packages/core`, `server` or `crates/render`: put before/after numbers on the worst case in the PR (Go CPU profile or timings for the server; script/layout/style time, long tasks and frame times for the canvas). (b) A worst-case performance test is mandatory for a hot path: the `perf` suite (`packages/e2e/test/perf`) runs against a synthetic worst-case document and fails when an enforced budget is exceeded; a feature that adds a hot path adds its scenario and budget. A PR that meets a budget flips its `enforce` to `true`. Worst case, budgets and how to profile: [performance](docs/en-US/performance.md). For `apps/web` there is no such scenario yet (the Go server does not serve it): its commit-count tests in Vitest and the manual `?perf=1` measure are not that budget, as the performance page says.
8. UI SDK skill: `.claude/skills/ui-sdk/` is the upstream Vercel Labs skill, vendored unchanged (`skills-lock.json`; identical to `node_modules/@ui-sdk/core/skills/ui-sdk`) and applies to `apps/web` only, never to `web-legacy` or `apps/site`. Where it disagrees with this file, this file wins: in `apps/web` components come from the UI SDK, styled with Tailwind on the theme tokens and wrapped in `src/components/ui/`, where every simple component lives and only renders: data comes in by props and events go out by callbacks, with no context state (i18n, router, Query, stores), no API calls and no business effects; local state is only the minimum interaction state the headless primitive needs, and a controlled form (`value`/`onValueChange`, `open`/`onOpenChange`) is offered whenever it makes sense; all visible text and `aria-label`s arrive by props; `@ui-sdk/core/web.css` is not imported; shadcn and Radix stay in `web-legacy` only; `pnpm`, never `npm`; no package installs, test frameworks, WebMCP/`registerTools` exposure or global stylesheet imports unless the task asks for them; never mark a failing test `test.fails` to keep a suite green; rules 6 and 7 and the Verification section still apply. `apps/web` has two component layers: `src/components/ui/` (render-only, as above) and `src/components/frontends/<name>/` (complex components that take external state by props and emit callbacks, with an `index.ts` and a `<name>.test.tsx`; they compose `ui/` components, may use i18n (`frontends.<name>.*` keys, complete labels, never a noun interpolated from the owner) and the external libraries on the whitelist (`@tanstack/react-store`, `@tanstack/react-virtual`, `@tanstack/react-hotkeys`, `uqr`, `lucide-react`, `@ui-sdk/*`, `@paprika/core`), and never touch the network, TanStack Query/DB/Router, `web-legacy` or another frontend's folder). Splitters, resizing and drag always come from the UI SDK primitives (`ui/resizable.tsx`), never a hand-written `role`. Hot pointer paths do no `setState` or owner callback per `pointermove`: the primitive writes CSS variables, the frontend emits on commit. Regional state lives in a TanStack Store made per instance with `createRegion` from `frontends/_shared` (typed actions, `Provider({ store?, initial? })`, `useRegion(selector, compare?)`) only when two or more components consume it or a row subscribes to its own slice; otherwise `useState`. State the owner controls is never mirrored in the store; the controlled form is `value` / `onValueChange` / `onValueCommit`. Every action that removes the focused element sets the next focus. Local preferences persist only through `src/lib/persist.ts` (`usePersistedState`, `readPersistedJson` with a validator), never document data, names or secrets, and never when the value is controlled. Use logical CSS properties (`ps-`, `pe-`, `start-`, `end-`). `src/components/architecture.test.ts` (run by `pnpm test`) enforces it: `frontends/` may import only the whitelisted packages, `ui/`, `_shared`, its own folder and the whitelisted `@/lib/*` modules (followed transitively, with the network rules applied to them); no `fetch` (also through `globalThis`/`window`/an alias or bracket access), `XMLHttpRequest`, `WebSocket`, `EventSource`, `Worker`, `sendBeacon`, dynamic imports with a computed specifier, `api(`, `localStorage`, `location`, `window.open`, hex colours or `dark:`, no store created at module scope; `ui/` must not import `frontends/`, i18n, router, store, query or `persist`. The app layer outside `components/` follows the same discipline (enforced by `src/test/architecture.ts`, tested in `src/test/app-architecture.test.ts`): only `src/data/**` touches the network (`api.ts` for HTTP; `live/` for `/ws`, a client without React made once by `LiveProvider`, read with `useLive(selector)`, written with `useLiveActions().apply(ops, label)`, a promise settled by the server's `ack`/`error`); `src/adapters/` are pure functions from server shapes to frontend props (`@paprika/core`, pure `lib/*`, and `import type` from `data` and the frontends only); containers in `src/editor/regions/*` and `src/overview/` read narrow slices, hand stable props and callbacks to the frontend and sit in `<RegionProfiler>` (`src/perf`, on only with `?perf=1` in dev or tests); the editor's shared state is the per-instance store of `src/editor/editor-store.ts`; no store, socket or client is created at module scope (also inside an object literal or a function called where it stands), no `/api` path is written in a string outside `data/`, and adapters take no storage, hook, impure `lib` module or top-level `let`; the editor's keys that act on the selection (`editor/shortcuts.ts`) are valid only with the focus on the page, the stage, the layers tree or the stage toolbar;  `src/test/live-harness.tsx` is the shared fake socket, N-node document and editor render for tests. `apps/web` needs `pnpm build` (or `pnpm --filter @paprika/core build`) before its typecheck and tests on a clean tree. Vitest and Testing Library are installed in `apps/web` for these tests. Bump `@ui-sdk/*` and the skill together (`npx skills@latest add vercel-labs/ui --skill ui-sdk -a claude-code -y`).

## Verification

- `pnpm check` = build (TS + Go binary) + typecheck + fixtures up to date + TS and Go tests + API and E2E suites against the Go server. The WASM E2E runs only when the renderer was built (Rust + `wasm-bindgen-cli` 0.2.130 installed); `pnpm test:render` runs the Rust tests.
- `tb verify run` uses `.toolbelt/config.yaml`: gate steps `build_cmd` = `pnpm build` (TS + Go binary), `typecheck_cmd` = `pnpm typecheck`, `lint_cmd` = `pnpm go:vet`, then `test_cmd` = `pnpm test` (the unit tests of every workspace package: `@paprika/core` and `@paprika/web`), Go tests, and the API and E2E suites against the Go server. `tb` reads the `verify:` and `env:` sections **as committed at the base ref**, never from the working tree, so a change to them only takes effect after it merges (and `tb guard` reports `verify_config_changed` on the PR that makes it: say so in the PR). Re-running `tb init` never migrates an existing `config.yaml`; new keys are added by hand.
- If the machine's Playwright Chromium revision doesn't match the lockfile, run `pnpm --filter @paprika/e2e exec playwright install chromium` (or point `PAPRIKA_CHROMIUM` at an installed Chrome).
- Before calling work done or opening/updating a PR: `tb stack verify guard` must pass (add `--ticket rd.md` for review/drift). On a branch with several commits, check the whole range: `tb guard check "$(git merge-base origin/main HEAD)"..HEAD`. Never skip it because `tb` is missing: if the hook could not install it, run the same checks by hand and say in the PR that `tb` did not run and why. Known false positive (toolbelt 1.0.0-rc.3): a moved test file (`git mv`) is reported as `test_deletion` on its old path; check with `git diff -M --name-status <base>..HEAD` that every flagged file is an `R` entry whose new path is still a test, and list them in the PR.
- CI (pull requests only, see `docs/en-US/ci.md`): `node .github/scripts/ci-plan.mjs origin/main HEAD` shows which jobs your change triggers. Go lint: `cd server && golangci-lint run`.
- E2E needs Playwright's Chromium; under `tb`, `PLAYWRIGHT_BROWSERS_PATH` and `PAPRIKA_CHROMIUM` are in `env.allow`.
- Performance: `pnpm test:perf` (builds the Go binary; needs `pnpm build` for the browser scenarios and Chromium) runs the `perf` suite against a synthetic worst-case document, prints a `scenario | measured | budget | status` table and writes a JSON report to `$PAPRIKA_PERF_REPORT` (default `report.json` in a fresh `paprika-perf-report-*` directory under the OS temp dir; the path is printed). Budgets with `enforce: false` show as `known-failing` with their ticket and do not fail the run; it is not part of `pnpm check`. See [performance](docs/en-US/performance.md).

## Agent bus

Agents running on the maintainer's machine coordinate through the local toolbelt bus (channel `paprika`): see `docs/en-US/agent-bus.md` for how to join, the lanes that keep bus agents off the files the backlog stack is changing, and the claim → worktree → `complete` protocol. Claim a thread before editing anything; never work in the maintainer's checkout.
